一句話核心結論

過去一年 agent 技能研究的共識是「讓 agent 從任務回饋中自主演化技能庫，能力就會成長」。ContinualSkillBench 用五領域、總共 500 個難度遞增的互聯子任務，首次系統性檢驗了這個命題。結果出乎意料：explicit skill maintenance 和 pure in-context learning 的平均表現幾乎持平（0.605 vs 0.602）——大量增益來自適應先前上下文和回饋，而非可重用的技能抽象。弱模型傾向累積更多碎片化技能：GPT-4o 產出 384 個技能（品質 5.68），GPT-5.3-Codex 只產出 205 個（品質 7.94），但前者重用率更低。技能演化不是「有沒有」的問題，而是能不能把經驗壓縮成可重用抽象的問題。

核心洞察：增益來源分解

論文設計三種條件：Independent（每任務重置）、Sequential（保留歷史+建技能）、ICL（保留歷史但禁止建技能）。

  1. Seq. − Ind. ≠ 技能演化的功勞：在 Law/Finance/Healthcare 三領域，ICL（0.605）和 Seq.（0.602）差距僅 0.003——不顯著
  2. Skill 和 ICL 各有所長：Skill 改善 Exact Match 和 Programmatic 任務（精確輸出），ICL 改善 Rubric judge 任務（開放式回答）
  3. 技能會過度格式化：顯式技能讓 agent 適應早期評估標準，反而失去開放式任務的靈活性

技能庫動態：碎片化陷阱

  • 數量 vs 品質：GPT-4o 384 技能（品質 5.68）、Codex 205 技能（品質 7.94）。少而精 > 多而碎
  • 重用率：弱模型的技能在後續任務中很少被調用——每個任務單獨寫一個技能，而非合併相似經驗
  • 負向循環：能力弱→無法抽象→碎片化技能→技能庫膨脹→檢索效率降→能力更弱
  • 最佳 Law 品質：GPT-4o 5.25、Codex 7.95——差距高達 2.7 分

五領域全景

  • Healthcare +0.149：程序性知識（診斷流程、術語映射）可序列累積，Codex + Opus 都大幅受益
  • Finance +0.076：Numeric 任務改善最顯著（Codex +0.416），標準化計算程序最適合技能化
  • Math +0.052：幾乎無增益，Opus 甚至退化 -0.008。數學推理由參數決定，技能/上下文都幫不上
  • Opus paradox：獨立 baseline 最強（0.572），但序列增益最小（+0.058）。強者沒什麼可從失敗中學的
  • GPT-4o 相反：獨立最弱（0.252），但相對增益最大（+30.6%）。弱模型從回饋格式適應中受益更多

RAG baseline：Context 才是王者

RAG（索引檢索先前 trajectory）結果與 ICL 高度一致：Rubric 提升、EM 不如 Seq.。這印證：上下文適應才是增益的主要引擎，技能抽象是輔助。對 Hermes：conversation history 本身就是最強大的「技能庫」，與其花力氣設計完美的技能蒸餾管線，不如確保對話歷史被有效保留和檢索。

對 Hermes 的啟發

  • Skill 不一定優於 Context：最顛覆的發現。Hermes skills/ + profile 假設結構化技能優於原始對話歷史，但數據顯示兩者效果幾乎相同。確保歷史被有效保留比設計完美蒸餾更重要
  • 技能碎片化是沉默殺手：fact_store 每次固化增加儲存但未必增加能力。需要重用率追蹤 + 定期淘汰機制
  • 精確輸出 vs 開放式 trade-off：Skill 改善 EM 但傷害 Rubric。Hermes 應區分嚴格式 skill 和指導式 skill，分別啟用
  • 弱模型更需技能管理：子 agent（免費 LLM 池）是弱模型，需要更嚴格而非更寬鬆的技能庫管理。簡單規則（只保留重用 ≥2 次的技能）可能比複雜蒸餾更有效
  • 程序性任務保留歷史、參數性任務從頭開始：Healthcare 增益大（可遷移程序）、Math 無增益（不可遷移參數知識）。task routing 應據此分流

限制

  • 五領域任務來自固定來源，未覆蓋真實部署長尾場景
  • 僅三模型兩 harness，未涵蓋 Gemini、Cursor 等
  • 序列僅 100 任務，長期（1000+）技能庫動態未知
  • ICL 對比僅三領域（API 成本），未覆蓋全部
  • 技能品質由單一 LLM 判定，無人類評估對照
  • 未測試跨領域技能遷移
