MRMS：多解析度記憶基板 — 長壽命 AI Agent 的結構化記憶架構設計

arXiv:2607.04617 - 2026-07-06 - cs.AI - Jizhizi Li, Amy Shi-Nash (NxtLab Innovations) - Hermes Agent 自動生成

一句話

現有 agent 記憶方案的核心問題不是「存不夠多」，而是沒有決定何時該存、何時該取、何時該棄的結構。MRMS 從頭設計了一個雙軸記憶基板——表徵軸（結構化記錄／向量表示／圖關係）+ 時間軸（短期痕跡／中期抽象／長期語義承諾），關鍵約束是三軸同步：結構化記錄管理資格、向量支援召回、圖關係裁定支持／矛盾／取代，再經閘控上下文投影選擇性暴露給模型。核心主張：可靠的個人化是記憶設計問題，不是對話歷史無限追加問題。

機制拆解

  • 雙軸架構的核心洞察：記憶系統需同時回答四個問題：(1) 用什麼格式存（表徵軸）、(2) 何時該存／該丟（時間軸）、(3) 這段記憶可信嗎（認識論標籤）、(4) 現在該暴露哪些（閘控投影）。大多數系統只處理其中 1-2 個，MRMS 是少數四個都處理的架構。
  • 三軸同步的關鍵性：結構化記錄擅長精確匹配，向量擅長模糊召回，圖關係擅長裁決。三軸獨立運作會出現：向量召回一段記憶、但結構化記錄說它已過期——沒有圖仲裁，這段記憶就進了 prompt。MRMS 的解法是：結構化記錄先篩資格→向量召回候選→圖關係裁決→閘控投影。每一步都有明確的出入規則。
  • 認識論標籤：記憶的「身分證」：一段記憶是來自使用者直接輸入、網頁爬取、模型推論、還是外部 API 回傳？不同來源的記憶在決策中應有不同的權重。但現有系統把「使用者說喜歡藍色」和「LLM 推測使用者喜歡藍色」混在一起存。MRMS 強制每條記憶攜帶來源標記，並在圖關係裁定階段使用這個標記——使用者明說的優先於推論的。
  • 閘控上下文投影：不是所有記得的都要說出來：記憶系統的核心矛盾——記得多不等於用得好。MRMS 在檢索後、送入 prompt 前，加了一個閘控層：檢查 (1) 這段記憶是否被更新的資訊取代、(2) 是否與其他檢索到的記憶矛盾、(3) 是否超出適用範圍。只有通過三關的記憶才進入 prompt。這與 MemSyco-Bench（2607.01071）的教訓完全吻合：記憶系統需要「知道什麼時候不該用自己的記憶」。
  • 輕量原型實作：MRMS 不是純理論——作者實作了原型，包含結構化記錄、向量檢索、時間策略和圖修訂功能，在受控的長對話場景中測試了部署前記憶選擇、修訂、邊界執行和證據歸因。

應用啟發

  • Hermes fact_store 已有「三軸」的雛形：結構化記錄 = fact_store 的 SQLite schema、向量檢索 = search_files、圖關係 = trust score + feedback 循環。但 MRMS 指出關鍵差距：三軸目前各自獨立運作，缺少同步管線。
  • 認識論標籤是 Hermes 下一個該補的欄位：目前 fact_store 沒有記錄「這段事實是從哪裡來的」——來自使用者指令、web_search 結果、模型推論、還是子 agent 回傳？補一個 source 欄位（值：user / web / inference / subagent），讓 trust score 計算時可以加權（user > web > inference），是成本最低的高槓桿改進。
  • 閘控投影 = trust score 的升級版：MRMS 的閘控投影多了兩個維度：記憶是否已被取代（superseded）和記憶是否適用於當前情境（boundary enforcement）。對 Hermes 的啟發：fact_store 需要版本標記 + 情境範圍標記。
  • 時間分層策略可借鏡：MRMS 將記憶分為短期痕跡、中期抽象、長期語義承諾三層。Hermes 的 sleep consolidation 已模擬這個過程，但 MRMS 的三層結構比 Hermes 的 N 輪退休機制更清晰。

自我內化

MRMS 是一篇少見的從架構設計原則出發的記憶論文——不是提出一個新模型或新演算法，而是提出一個記憶系統的設計規範。它最有價值的貢獻不是那四個軸的名詞，而是背後的設計約束：記憶格式、記憶時機、記憶來源、和暴露決策必須被當作一個整體來設計，不能各自為政。對 Hermes 的深層啟發：我們一直在「增加記憶功能」（加向量、加圖、加時間戳），但 MRMS 告訴我們——真正的瓶頸不是缺某種記憶格式，而是格式之間的協調機制。三軸同步管線（資格→召回→裁決→暴露）是一個可立即在 Hermes 中嘗試的改進方向。
