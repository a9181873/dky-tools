Stanford CME 295（2025）九講導讀：從 Transformer 到 Agent

正文以 Stanford CME 295 2025 官方投影片 PDF 為逐講證據；YouTube 清單只核對九講名稱與順序，未完整觀看影片或取得逐字稿，故本文是投影片導讀，不是逐字摘要。版本說明見文末。

先抓住整門課的主線：文字先被切成 token，再由 Transformer 建立上下文表示；大語言模型靠預訓練學會延續文字，接著可經微調調整行為。推理是在作答前投入額外計算；RAG 補進外部資料，工具呼叫讓模型請外部系統執行動作，Agent 把多步驟組成可觀察的迴圈；最後還要用合適的評估方式判斷輸出與系統是否真的達標。

建議閱讀路線

若重點是搭建或評估 Agent，可先讀第 7 講（架構）、第 8 講（評估），再看第 6 講（推理）；完整建立基礎則依第 1 至第 9 講閱讀。這是概念地圖，不是官方課程重排。

  1. 表示：token、向量與注意力 → 架構：位置、正規化與模型家族
  2. 生成：MoE、解碼與推論效率 → 訓練：預訓練、平行化與微調 → 偏好：RLHF、PPO 與 DPO
  3. 推理：測試時計算與可驗證獎勵 → Agent：RAG、工具與行動迴圈 → 評估：指標、裁判模型與基準 → 延伸：視覺、擴散式 LLM 與趨勢

第 1 講｜Transformer：從文字到上下文表示

核心概念。課程以分類、命名實體辨識、翻譯與生成引入 NLP，再走過 tokenization、詞向量、RNN／LSTM、注意力與 Transformer。子詞切分可降低未見詞問題，但不一定符合人的詞語直覺。Word2vec 與 RNN／LSTM 提供脈絡；自注意力以 Query、Key、Value 建立 token 關聯，Transformer 將其堆疊並平行運算。

帶走一句：模型不是直接「讀懂句子」；它先把離散文字轉成向量，再依上下文更新各 token 的表示，並以逐 token 預測完成生成。

常見誤解與應用映射。向量相近不等於完整理解，注意力權重也不是解釋證明。整理合成客服留言時，先區分分類（情緒／意圖）和生成（摘要／回覆），再選輸出與評估方式。

投影片依據：tokenization、詞表示與 Transformer 流程，第 28–33、37–49、51–89、90–134 頁。原始來源 [1] · 影片播放入口

第 2 講｜Transformer 模型與技巧：補位置、顧穩定、降成本

核心概念。注意力不會自動保留 token 順序，因此需加入位置資訊；投影片比較絕對位置嵌入、相對偏置與旋轉位置嵌入（RoPE），並說明正規化的穩定作用。長序列與記憶體限制帶來稀疏注意力、共享 Key／Value 的 MQA／GQA。後半以 BERT 對照 encoder-only、decoder-only、encoder-decoder 模型，並介紹遮蔽語言模型與下游微調。

帶走一句：模型架構的「技巧」不是裝飾；它們是在序列長度、表達能力、訓練穩定與計算／記憶體成本之間取捨。

常見誤解與應用映射。RoPE 或長上下文不等於可靠長期記憶，也不保證長文件資訊都同樣有效。處理合成政策文件時，先分辨全文理解、分類或生成，再確認上下文限制；最大支援長度不等於可用證據範圍。

投影片依據：位置表示與 RoPE 第 12–35 頁、正規化第 37–44 頁、注意力變體第 46–54 頁、BERT 與 encoder-only 第 62–108 頁。原始來源 [2] · 影片播放入口

第 3 講｜大型語言模型：模型家族、生成與推論效率

核心概念。課程把 LLM 描述為以 Transformer 為基礎、透過預測 token 機率生成文字的模型，並介紹混合專家（MoE）：路由器依 token 選擇部分專家運算，省下每一步啟用所有參數的成本，但也帶來路由不平衡等訓練難題。生成方面，greedy、beam search 與抽樣是不同解碼策略；temperature、top-k／top-p 改變候選分布與多樣性，受限解碼則讓輸出遵守指定結構。後段看 KV cache、GQA、PagedAttention、speculative decoding 與多 token 預測等效率方法。

帶走一句：同一組模型權重，解碼策略與推論架構不同，輸出的穩定性、格式、延遲與資源需求也會不同。

常見誤解與應用映射。合法 JSON 不代表欄位正確；MoE 總參數也不等於每個 token 都運算全部參數。從合成理賠文件抽欄位時，格式約束與原文證據要分開驗證，再依品質需求選擇解碼方式。

投影片依據：MoE 第 17–31 頁、解碼與結構化輸出第 33–75 頁、推論效率第 87–124 頁。原始來源 [3] · 影片播放入口

第 4 講｜LLM 訓練：預訓練、系統效率與監督式微調

核心概念。預訓練以大量文字與程式碼學習下一 token 預測，讓模型形成通用語言能力；它不是替某個單一任務寫好的規則。課程接著談資料／模型平行化、ZeRO、FlashAttention 與混合精度等訓練系統技巧，最後介紹監督式微調（SFT）如何以示範輸出改變模型行為，以及 LoRA／QLoRA 如何只訓練低秩增量、或量化凍結權重來降低微調資源門檻。

帶走一句：預訓練建立廣泛的續寫能力，SFT 讓模型模仿指定任務的示範；兩者資料、目標與成本都不同。

常見誤解與應用映射。微調不會自動補進新文件，也不保證未見情境可靠；LoRA 仍需訓練。固定合成摘要格式可先整理示範與驗收，再評估 SFT；需更新事實則用檢索，不要硬寫入權重。

投影片依據：預訓練與 scaling 第 14–27 頁、訓練平行化與 FlashAttention 第 29–81 頁、SFT 與任務行為第 84–102 頁、LoRA／QLoRA 第 106–127 頁。原始來源 [4] · 影片播放入口

第 5 講｜LLM 調整：偏好資料、RLHF 與 DPO

核心概念。當「像示範那樣回答」不足以表達偏好時，可收集同一提示下較佳與較差的回答。RLHF 通常先用偏好比較訓練獎勵模型，再透過強化學習（投影片以 PPO 為例）更新語言模型，並限制它不要偏離基礎模型太遠。DPO 則把偏好目標改寫成較直接的監督式最佳化，不必分開訓練同一種獎勵模型；Best-of-N 是推論時生成多個候選、再按分數挑選的另一種路徑。

帶走一句：偏好調整的品質上限受偏好資料與評分方式牽制；演算法不能替有偏或含糊的標註背書。

常見誤解與應用映射。DPO 仍依賴偏好資料；PPO 也非加獎勵就能安全對齊。改善合成文件問答的語氣或拒答行為時，先建立成對範例並確認標註準則，再選偏好調整或提示／SFT。

投影片依據：偏好資料第 15–21 頁、RLHF／獎勵模型與 PPO 第 31–82 頁、Best-of-N 與 DPO 第 83–107 頁。原始來源 [5] · 影片播放入口

第 6 講｜LLM 推理：把更多計算留給難題

核心概念。鏈式思考（Chain-of-Thought）把中間步驟納入解題，推理模型則增加作答前的測試時計算。對數學答案或程式測試等可驗證任務，可用結果正確性作強化學習獎勵；GRPO 以同題候選的相對表現估計優勢，並與 PPO 比較。投影片亦談長度膨脹、探索多樣性及 R1 訓練與蒸餾。

帶走一句：增加作答時的計算能擴大搜尋與驗證機會，但「輸出更長」和「推理正確」不是同一件事。

常見誤解與應用映射。推理文字不等於可驗證的內在思考。分析合成報表時，可由檢查器驗算、模型提出解釋，再以數據核對；只有可自動驗證的部分適合直接當獎勵，開放式判斷仍需評審。

投影片依據：推理概念與 benchmark 第 16–47 頁、測試時計算與獎勵第 49–67 頁、GRPO／R1 訓練與蒸餾第 69–147 頁。原始來源 [6] · 影片播放入口

第 7 講｜Agentic LLM：檢索、工具呼叫與行動迴圈

核心概念。RAG（檢索增強生成）從知識庫找資料、排序，再把片段放進提示；召回率與精確率服務於不同階段。工具呼叫依描述選 API、填參數，由系統執行並回傳。Agent 把觀察、規劃、行動串成迴圈；ReAct 展示推理與行動交替，MCP 連接模型與工具／資料，A2A 探索 Agent 協作，並伴隨安全風險。

帶走一句：RAG 是「找資料並帶入上下文」，工具呼叫是「請外部功能執行」，Agent 是「組織多步驟目標與狀態」；三者可以組合，但不是同義詞。

常見誤解與應用映射。找到文件不代表答案有根據，工具成功也不代表回傳正確；Agent 可能選錯工具、參數或越權。合成資料助理可先只讀取表格並列出依據，寫入或寄送等副作用則要求人確認。2025 本講聚焦 RAG、工具與 Agent，不挪用新版材料。

投影片依據：RAG 與 retrieval/ranking 第 20–76 頁、工具呼叫與 MCP 第 80–115 頁、Agent／ReAct／A2A 與安全第 116–150 頁。原始來源 [7] · 影片播放入口

第 8 講｜LLM 評估：從回答品質到系統可靠性

核心概念。評估分為輸出品質（遵循指令、事實性）與系統表現（延遲、費用、可靠性）。BLEU、ROUGE、METEOR 可重複計算，但可能漏掉改寫與語境；LLM-as-a-Judge 可按準則評分，卻有位置、冗長與自我偏好偏差，需清楚規準並抽樣人工校準。Agent 評估要定位工具、參數、回傳或最終答覆的失敗；基準依知識、推理、程式、安全或 Agent 任務選用，並留意資料污染與 Goodhart 效應。

帶走一句：指標是目標某個面的投影，不是「模型整體好壞」的單一真相；先定義任務，再選對量尺。

常見誤解與應用映射。LLM 評審不是人工真值，也不是把主觀判斷變客觀；benchmark 高分也可能受訓練資料污染或測試條件影響。若比較合成文件問答系統，應分開量測答案正確與引用支持、工具流程成功、失敗復原及延遲，再用人工作為抽查基準，不能只看單一總分。

投影片依據：評估範圍與規則式指標第 9–37 頁、LLM 裁判與偏差第 39–95 頁、Agent 故障模式第 97–136 頁、基準與限制第 137–168 頁。原始來源 [8] · 影片播放入口

第 9 講｜回顧與趨勢：Transformer 的邊界之外

核心概念。前段回顧全課，再說明 Transformer 延伸至視覺：Vision Transformer 將影像切成 patch 序列，視覺語言模型把圖像表示接入語言模型。擴散式語言模型則以遮罩和多輪去遮罩生成文字，不同於自回歸逐 token 生成。課程也談基礎研究、硬體／品質成本取捨與幻覺挑戰。

帶走一句：新架構帶來新的生成與效率取捨；應先問它改善哪種任務、付出哪些成本，而不是只追逐新名稱。

常見誤解與應用映射。介紹新架構不等於證明它全面勝過自回歸模型，課堂觀察也不是今日市場定論。評估多模態文件助理時，先拆分頁面辨識、文字引用與問答，再比較適配性和資源需求。

投影片依據：ViT／VLM 第 43–69 頁、擴散式 LLM 第 71–98 頁、趨勢與未解問題第 100–124 頁。原始來源 [9] · 影片播放入口

五個容易混在一起的概念

概念主要改變什麼不等於什麼
微調以示範或偏好資料調整模型權重／行為。不是即時查資料，也不保證知識永遠最新。
RAG每次任務檢索外部證據並置入上下文。不會因此自動修改模型權重；檢索結果也未必正確。
工具呼叫模型提出工具名稱與參數，由外部執行並回傳結果。不是單純把文件貼進提示，也不是工具本身的正確性保證。
記憶一般系統設計中的持續狀態／歷史資訊管理。不等於當次 RAG 檢索。2025 投影片雖談 KV cache 等運算記憶體，未把 Agent 的持續記憶列為獨立主題。
模型／系統評估模型評估看輸出能力；系統評估也看流程、成本、延遲與可靠性。不是 Agent 內的一個工具，也不能以單一 benchmark 代表全貌。

這些元件可以組合，但需分別記錄輸入、輸出與失敗原因：檢索漏資料、模型未呼叫工具、工具回錯或微調退化，都是不同診斷項目。
