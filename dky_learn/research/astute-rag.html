Astute RAG 研究筆記

一句話摘要：Astute RAG 是一種新穎的檢索增強生成方法，通過自適應 elicitation、迭代 consolidation 和可靠性 기반 最終答案選擇，有效克服不完美檢索和知識衝突，提升大型語言模型的可信度。

方法拆解（三步驟）

  1. 自適應 elicitation（適應性 elicitation）

    從 LLM 的內部知識中提取與查詢相關的關鍵資訊，以補充或校正檢索結果中可能的噪聲或錯誤。

  2. 迭代 consolidation（來源感知的迴融）

    在明確來源標記的框架下，將內部 elicitation 知識與外部檢索知識進行多輪融合，逐步降低無關或誤導性資訊的影響。

  3. 可靠性 based 最終答案選擇（可靠性驅動的答案選擇）

    根據資訊的可靠度（來源可信度、內部一致性、交叉驗證等）為每個候選答案打分，選擇分數最高的作為最終輸出。

關鍵數據

  • 實驗使用 Gemini 與 Claude 兩種大型語言模型。
  • 在最糟檢索條件下（含大量無關、誤導或對抗性內容），Astute RAG 是唯一能達到或超越傳統 LLM 單獨使用性能的 RAG 方法。
  • 相較於先前的 robustness‑enhanced RAG 基線，Astute RAG 在知識衝突情境下顯著提升答案正確率（具體提升幅度依資料集而異，但皆達統計顯著差異）。
  • 進一步分析顯示，該方法有效解決 LLM 內部知識與外部檢索知識的衝突，進而提升系統的可信度與穩健性。

對 Hermes 應用分析

對應 content-curation-pipeline 的環節

Hermes 的內容策展管線（content-curation-pipeline）大致可分為四個階段：

  1. 資訊蒐集（Web Search、Web Extract 等工具）
  2. 相關性過濾與去噪
  3. 知識整合（寫入記憶庫、建立關聯）
  4. 輸出生成（回答、報告等）

Astute RAG 的核心功能適合作為「相關性過濾與去噪」以及「知識整合」之間的橋梁，特別是在後檢索階段處理不完整或有衝突的資訊。

目前 Hermes 可能缺少的機制

  • 缺乏自適適從 LLM 內部知識中 elicitation 關鍵線索的步驟；多依賴檢索分數或關鍵字匹配。
  • 缺少來源感知的迭代融合機制，難以在多輪資訊交互中區分可信來源與噪聲。
  • 缺乏基於可靠性的最終答案選擇，易於將低品質資訊直接寫入記憶。

如何補充

  1. 在 web_extract 取得原始網頁內容後，插入一個 Astute RAG 處理模組：
    • 呼叫 LLM 進行自適應 elicitation，產生內部知識提示。
    • 以來源標記（URL、域名等）為基礎，執行迭代 consolidation，將內部提示與外部文本進行加權合併。
    • 設計可靠度評分函數（如來源權威度、跨來源一致性、LLM 自我評估），選擇最高分數的知識塊。
  2. 將經 Astute RAG 篩選後的知識塊送往 Hermes 的記憶系統（Honcho 跨階段記憶或技能庫），作為後續生成的依據。
  3. 此過程可作為可選技能（skill）或工具集（toolset）掛載，僅在偵測到檢索品質低落時啟用，以節省成本。

限制

  • 額外的 LLM 推理成本：每次 elicitation 與 consolidation 都需要調用模型，可能增加延遲與費用。
  • 依賴 LLM 內部知識的正確性：若模型本身包含錯誤知識，elicit 內容可能帶來偏差。
  • 在極端對抗性檢索（大量精心構造的誤導資訊）下，仍有可能被騙過可靠性評分。
